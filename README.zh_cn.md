# Better Removal

[English](README.md) | 中文

Fabric 1.20.1：按住 **左 Alt**（可改键）**右键**容器，直接把物品取进背包 —— **不用打开 GUI**。
- **空手** = 取出；**手持物品** = 放入。
- 按住**模式键**滚轮切换预设，松开生效：

| 预设 | 效果 |
|---|---|
| 取出 · 输出槽（默认） | 只取输出槽 |
| 取出 · 输入槽 / 燃料槽 / 全部 | 按名字取对应槽位 |
| 放入 · 输入槽 / 燃料槽 | 放进对应槽位 |
| 补货 | 用背包里已有的同类物品补满输入/燃料槽（空槽不补） |
| 手动指认 | 打开容器界面让你标出各槽位|

放入会遵守容器自己的槽位过滤（熔炉燃料槽只收燃料）。

**依赖**：Configured 必须安装；Jade 可选（工具提示预览）。

| 指令 | 作用 |
|---|---|
| `/br list [关键字]` | 列出已指认的容器（行尾 `[-]` 点一下删除该映射） |
| `/br delete <匹配串>` | 删除一条指认映射（也可以直接敲，或点 `/br list` 行尾的 `[-]`） |
| `/br reload` | 重新读取槽位规则与指认映射（改完配置不用重启） |

## 支持的容器

槽位布局由 `better-removal/containers/*.json` 数据驱动（见下一节），所以下面是内置规则覆盖的范围。

| 容器 | 取出 | 放入（输入 / 燃料） |
|---|---|---|
| 熔炉 · 高炉 · 烟熏炉 | 是 | 输入槽 / 燃料槽 |
| 酿造台 | 是 | 材料槽 / 烈焰粉 |
| 漏斗 · 发射器 · 投掷器 | 是 | 每个槽位 |
| 农夫乐事 木篮/竹篮 | 是 | 每个槽位 |
| 农夫乐事 厨锅 ※ | 是 | 输入槽 |
| 懒人厨房 烤炉 ※ | 是 | 输入 / 燃料 |
| Ad Astra 压缩机 · 电力高炉 · 燃油精炼机 · 氧气装载机 · 低温冷冻机 | 是 | 各输入槽（精炼机/装载机含流体输入） |
| Crabber's Delight 捕蟹笼 | 是 | 诱饵槽 |
| 天境 冷冻机 · 神能炉 | 是 | 输入 / 燃料 |
| Vinery 陈酿桶 · 苹果压榨器 | 是 | 各输入槽 / 酒瓶槽 |
| 沉浸农艺 烹饪锅 · 烤盘 | 是 | 输入 / 盘槽 |
| 沉浸农艺 炉灶 | 是 | 输入 / 燃料 |
| 考古与化石 分析仪 | 是 | 各输入槽 |
| 考古与化石 筛子 | 是 | 输入槽 |
| 考古与化石 培养槽 · 考古工作台 | 是 | 输入 / 燃料 |
| Iron Furnaces（全等级） | 是 | 输入槽 / 燃料槽 |

> ※ 这两个是仅有的**无法用规则寻址**的容器：它们的方块实体没有实现原版 `Inventory`，槽位号对规则没有意义，所以只能硬编码在代码里。
> 也正因为内置实现排在手动指认之前，这两个容器**默认接不上手动指认**——同一个方块永远先命中内置实现，只有先把它们的容器开关关掉，手动映射才有机会生效。

## 手动指认（支持其它任意容器）

> **实验性功能，默认关闭**：先在 Configured 的「实验性」里打开 **手动槽位指认**，模式滚轮才会出现「手动指认」。

有些模组把库存藏在私有的 `ItemStackHandler` 里、也没有实现 `Inventory`，这种容器槽位号是无意义的；
但它的 **GUI 菜单**总能寻址到槽位——菜单里的 `Slot` 直接持有背后那个容器的引用。手动指认用的就是这一点。

1. 在模式滚轮里选到 **手动指认**（按住模式键滚轮）。
2. 按住修饰键右击容器：这一次界面**正常打开**（不拦截、不搬物品）。
3. 滚轮换画笔，顺序是 **输入 → 输出 → 燃料 → 忽略**（向下滚前进一档；第一次滚动先把画笔设为「输入」）；
   按住修饰键把鼠标**滑过 / 停在槽位上**（约 0.1 秒）就把它涂成当前画笔的角色。
   界面会画出彩色区域和右上角字母（I / F / O）显示每个槽位的标签。
4. 关掉界面即可。映射保存在服务端的 `config/better-removal/menu-maps.json`。

之后这个容器就和内置支持的容器一样，可以不开界面直接取出/放入/补货——标签决定各操作碰哪些槽位。

几点要知道的：

- 映射按方块 ID 记录。
- 指认过程中模组会验证"这个容器的菜单能不能在没有界面的情况下重建"；如果不能（例如界面是方块自己创建的、
  不在方块实体上），会当场告诉你，并且不会保存这条映射。
- 如果容器已经有内置规则，内置规则优先；只有没有规则命中时才会用手动映射。
- `/br reload` 会重新读取 `menu-maps.json`。

## 兼容性

**FTB Ultimine**：同时按住修饰键与 Ultimine 键再右键，会对当前连锁形状里的每个受支持容器各操作一次。
（两端都要装，按键状态与连锁形状由服务端管理。）

**Jade**：按住修饰键看向容器，提示框显示即将取出/放入的物品。触发连锁时显示所有连锁容器的合计。
可用配置里的 **Jade 预览** 关掉。（想让预览显示真实内容，两端都要装。）

## 配置

通过 **Configured** 模组修改。每个容器默认开启，**只显示你实际安装了的模组**的分类。

---

### 一行式写法

```
ironfurnaces input=0 fuel=1 output=2
somemod:crusher,somemod:grinder input=* output=9,10
```

槽位用逗号分隔，`*` 表示全部槽位。角色有 `input`、`fuel`、`output`、`ignore`。
后面的赋值覆盖前面的，所以 `output=* ignore=5` 意思是「除 5 号槽外都是输出槽」。
写错的规则会被跳过并在日志里说明原因。

### JSON 写法

内置兼容与模组自声明走这个格式，放在 `better-removal/containers/*.json`：

```json
{
  "containers": [
    {
      "match": "somemod:crusher, @somemod.common.block.entity.CrusherBlockEntity",
      "config": "crusher",
      "size": 4,
      "extract": { "input": [0, 1], "fuel": [2], "output": [3] },
      "deposit": { "input": [0, 1], "fuel": [2] }
    }
  ]
}
```

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `match` | 是 | 匹配串，逗号分隔可写多个候选，命中任意一个即匹配 |
| `extract` / `deposit` | `extract` 必填 | 取出 / 放入方向的槽位表；两个方向不一样时才需要分别写 |
| `config` | 否 | Configured 里的开关键名；不写就没有独立开关、永远生效 |
| `group` | 否 | 开关所属分组；不写就从 `match` 的命名空间推断，`match` 只写 `@类名` 时必须显式声明 |
| `default` | 否 | 上面开关的默认值，缺省 `true` |
| `size` | 否 | 槽位总数；用于启动时检查槽位号是否越界、运行时报不一致 |
| `sided` | 否 | `true` 时取出前额外经过 `canExtract` 校验 |

> 只有带 `config` 键的规则才会出现在 Configured 里，也才可能被玩家关掉。

### 自检

`/br reload` 后生效。加载规则时日志会指出写错的地方：方块 ID 不存在、配置键重复、
槽位号超出声明的 `size`、规则没声明任何槽位。

### 主动探测：让模组替你读一遍槽位

打开 `主动探测模式`（默认关闭）后，模式滚轮会多出一项「主动探测」：按住修饰键右击任意容器，
模组会问容器自己的 inventory接口（`Inventory#isValid` / `SidedInventory#canExtract`），
把结果输出成一行**可点击复制**的规则串，粘进 Configured 的「容器槽位规则（声明式）」即可。
探测只输出文本，不会接管容器。（日志里那行 `[container] <方块> -> 0=INPUT 1=FUEL 2=OUTPUT ...` 是**声明式规则**命中时打印的，探测本身不写日志。）

它只能覆盖实现了原版 `Inventory` 的容器——槽位号对其它容器没有意义。
GUI 里有槽位、但方块实体没实现 `Inventory` 的容器（厨锅、各种机器），改走**手动指认**那条路。
